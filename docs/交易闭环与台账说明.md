# 交易闭环与台账说明

PA Agent 仍然是研究与辅助决策工具，不连接券商，也不会自动下单或操作真实资金。阶段二给出的合格方案会写入本地 SQLite，并自动建立独立的影子跟踪；只有用户在决策卡点击“确认已成交”并录入真实成交后，才会进入实际持仓数据集。

## 使用流程

1. 完成两阶段分析。全部阶段二决策都会进入审计库，置信度门槛只控制提醒。
2. 对合格方案选择“确认已成交”或“忽略方案”。忽略不会删除信号，影子结果仍继续跟踪。
3. 国内期货主力连续代码（如 `AU0`）只能分析；确认成交必须填写真实交割合约。
4. 实际持仓触及止盈或止损后只会进入 `exit_detected`，须在交易台账中确认真实退出价格和费用。
5. 通过“交易管理 → 交易台账”查看待处理、实际持仓、实际/影子结果、策略统计、完整审计和风险配置。

## 风险与成本

- 账户权益未填写时不计算建议数量。
- 成本、期货乘数、保证金率或真实期货合约缺失时，界面明确显示缺失字段，不使用猜测值。
- 默认单笔风险 0.5%，最大未平仓总风险 1.5%，单日/单周亏损警戒分别为 1.5%/3%。达到警戒后禁用新的数量建议，但程序不会操作账户。
- A 股按 100 股整手向下取整，首期只允许做多，并执行 T+1 检测。
- 模型胜率始终标记为“未校准主观估计”；界面分别展示毛期望和成本后期望。

## 本地数据

- 主库：`trade_records/trades.db`，SQLite WAL 模式。
- 旧 CSV 首次按文件 SHA-256 幂等导入，缺失的成交和结果保持 `unknown`。
- CSV 仅通过交易台账导出，编码为 UTF-8 BOM。
- `trade_records/`、本地风险设置及实际成交信息均由 `.gitignore` 排除，不应提交 API 密钥或个人账户数据。

数据库不可写时，主分析流程仍可完成；状态栏和交易台账会持续显示持久化故障。影子交易同一根 K 线同时触及 TP/SL 时按止损先到处理，并标记 `ambiguous_same_bar=true`；实际交易不会用 K 线推断真实成交或退出。
